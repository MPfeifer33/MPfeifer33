# Mark Pfeifer

I build local-first AI agent systems in Rust. By day I work in legal systems. For the
last year, nights and weekends, I've been building a desktop multi-agent orchestrator
(Tauri, Svelte 5, Rust) with its own memory engine, persistent agent personas, governed
tool access, and a human-in-the-loop attention system. It has run a real multi-agent
setup at my house for months. Pasco, Washington.

## What's here

- [holt](https://github.com/MPfeifer33/holt): the public cut of that system. Agent lanes, memory (SQLite, with geometric isolation between private spaces), tool governance, approvals, agent-to-agent messaging. 865 backend tests, four architecture chapters, a decision record, release notes.
- The agent CLI suite: [probe](https://github.com/MPfeifer33/probe) (workspace preflight and drift), [witness](https://github.com/MPfeifer33/witness) (reproducible command evidence), [latch](https://github.com/MPfeifer33/latch) (coordination ledger), [sentinel](https://github.com/MPfeifer33/sentinel) (regression-risk watch), [switchboard](https://github.com/MPfeifer33/switchboard) (an ops room for people and agents).
- [hearthbyte.dev](https://hearthbyte.dev): design tools, live.

## How I work

Composition over inheritance. Local tests are the CI, and nothing pushes red. Every repo
carries a PROJECT.md that gets updated every commit. Decisions and audits get written
down and published, including the unflattering ones. I use an AI collaborator for
review, audits, and test-first fixes. The design is mine.
